### Variante B: PAS

```text
KI-Modelle sind erstaunlich schlecht darin, ihre eigene Arbeit kritisch zu prüfen. Wenn dasselbe Modell erst den Code schreibt und danach seinen eigenen Fehler suchen soll, übersieht es oft genau die Annahmen, die es vorher selbst getroffen hat. Das wird spätestens dann teuer, wenn kleine Fehler in ein echtes Projekt wandern.

OpenAI hat dafür ein offizielles Codex-Plugin für Claude Code veröffentlicht. Damit kann Claude zuerst bauen und Codex danach die Änderungen getrennt prüfen. Mit /codex:review lässt du den aktuellen Stand untersuchen. /codex:adversarial-review sucht gezielt nach Schwachstellen. Wenn Claude festhängt, liefert /codex:rescue einen zweiten Ansatz. Jeder dieser Schritte wird bewusst von dir gestartet.

Wenn du den offiziellen Repo-Link, die Installationsanleitung und meinen Build-und-Review-Ablauf haben willst, kommentiere TEAM und ich schicke dir alles zu.
```

### Variante C: BBB

```text
Claude Code und Codex können zusammen wie ein Build-und-Review-Team arbeiten.

Der Vorteil entsteht durch die Trennung der Rollen. Claude setzt die Aufgabe um. Codex prüft anschließend die Änderungen aus einer zweiten Perspektive oder übernimmt eine klar abgegrenzte Teilaufgabe. So hängt die Qualitätskontrolle nicht allein an dem Modell, das den ersten Entwurf gebaut hat.

Ein Beispiel: Claude implementiert eine Funktion. Danach startest du /codex:review für die normale Prüfung. Mit /codex:adversarial-review lässt du gezielt nach problematischen Annahmen und Fehlern suchen. Bei einer Blockade holst du mit /codex:rescue einen zweiten Lösungsweg ein.

Wenn du den offiziellen Repo-Link, die Installationsanleitung und meinen Build-und-Review-Ablauf haben willst, kommentiere TEAM und ich schicke dir alles zu.
```
